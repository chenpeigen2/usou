v1.7.13 失效路径保护：让「打开一个已经不存在的文件」**不再静默、也不再把应用拖死**。上一轮中断时留下的线索本轮用**独立探针实测**跑出了结论：`shell.openPath(<不存在的路径>)` 返回的 Promise **永不落地**（5/5 用例 25s 超时未 settle），Windows 还会弹出一个**模态原生错误框**（窗口标题就是那个缺失路径）⇒ 渲染层 `await` 永远挂着，用户只看到「点了没反应」+ 莫名弹窗；但**主进程并没有被挂起**（25s 内心跳 230~231 次、最长间隔 0~7ms）⇒ 真正的问题是「**IPC Promise 悬空 + 原生模态弹窗**」，而不是「主进程冻结」；另一侧 `shell.showItemInFolder(<不存在的路径>)` 则**同步返回、什么都不做** ⇒ 「打开所在目录」是 **100% 静默失败**（`path:show` 直接 `return true`，渲染层也完全忽略返回值）。两者**同根因**：扫描缓存里存着已被删除的路径（实测 60 条里 **36 条已失效**），而打开前从不判存在性。现在**主进程打开前先判存在性**：不存在就直接返回错误信息、**根本不调 shell**（既不悬空也不弹原生对话框），存在的再加一道 `Promise.race` 15s 超时兜底（路径存在但系统打不开时的防御）；`path:show` 改为返回 `{ok, reason}`，渲染层按 `ok===false` 弹提示。渲染层再把失效条目**显式标出来**：一次**批量** IPC 查存在性（避免 60 次 IPC 风暴），失效行**置灰 + 划线 + 红色「已删除」角标**（角标占用「文件类型」那一格 ⇒ 网格列数不变、零布局位移），点它会明确告诉你「路径已不存在」，而不是对着空气点击。新增 `path:exists` 批量通道（只增不改名），零外部依赖。

v1.7.12 搜索能力补齐：让「万物直达」真的**直达得到**。此前搜索内核只有一种匹配 —— 要求查询串在整条索引里**连续出现**，于是**多词查询 100% 失效**：用真实扫描缓存量化，雷达里明明有 **7 个 TclLauncher 项目**，而「tcl launcher」「code launcher」「tcl launcher hotapp」「tcllnch」「3dww」「gzq」**全部 0 命中**（项目视图的搜索框是同一处缺陷的第二份拷贝）。现在换成一套搜索内核：**分词 AND**（空格/逗号/顿号分词，词序无关）+ **子序列模糊**（`tcllnch` → TclLauncher）+ **拼音首字母**（`gzq` → 工作区、`3dww` → 3d娃娃）+ **相关性排序**（前缀 > 包含 > 拼音 > 模糊；同分保原序 ⇒ 「收藏恒置顶」不受破坏；AND 无命中时降级为「仅按名称 OR」并排在 AND 结果之后）。拼音表**不是手写**的：用 Node 内置 ICU 的 `zh-u-co-pinyin` 排序推断 + **355 条已知拼音的断言自证**生成（419 字，独立反查 0 违规），未收录的字优雅降级（保留原字，不产生错误结果）。另外补齐两处交互不一致：「最近」视图 60 条记录**终于有了搜索框**（此前项目视图有、最近视图没有），**最近文件也进了命令面板**（PAL 81 → 143 条）；顺手修掉 palette 的脏键（`p.branch` 为 null 时索引里会混进字面量 `undefined`）。零新增 IPC、零外部依赖。

## 启动

三选一：

1. **安装版**：双击 `out\Workbench-Setup-1.1.0.exe` 安装（桌面出现「工作台」快捷方式）
2. **便携版**：解压 `out\Workbench-1.1.0-portable.zip`，运行 `工作台.exe`
3. **开发态**：双击 `start.cmd`（或 `npm start`）

- 首次启动无缓存会自动开始全量扫描（约 4 分钟，标题栏中央有实时进度）

- 无头刷新缓存：`node run-scan.js`（不出窗口，跑完写缓存）

## 架构

```
main.js           主进程：窗口 + IPC（扫描/打开/git/分析/设置）
preload.js        contextBridge 白名单 API（window.wb），渲染进程无 Node 权限
src/scanner.js    扫描器（scan.ps1 的 Node 移植 + 空间分析/能力探测）
src/store.js      缓存与设置持久化（data\scan-cache.json / settings.json）
renderer/         UI（无框架 vanilla JS + CSP：default-src 'self'）
runtime/electron/ 内置 Electron v33.4.11（268MB，来自 IKanBot node_modules 复制）
data/             运行时数据（可随时删除重建）
```

安全模型：contextIsolation 开、nodeIntegration 关、CSP 限 self、
所有管理动作均为只读/打开类操作，无删除等破坏性操作。

## 已知环境坑

- 若从 VS Code / DSH 终端启动，需清掉 `ELECTRON_RUN_AS_NODE`（start.cmd 已防御处理）。
- 未提交数不含未跟踪文件（git status -uno，大仓库提速取舍）。
