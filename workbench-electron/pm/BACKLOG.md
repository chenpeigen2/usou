## 本轮巡检发现的真实问题（待升级为 READY）

- **P2 · 浅色主题 hover 态对比度不达标（第二十六轮自查发现，本轮已修）**：浅色主题的项目类型徽章 `.badge.Android` 在**行被 hover**（行底 `--panel` → `--panel2`）时实测 **4.36:1 < WCAG AA 4.5:1**（不 hover 时 4.67:1 通过）。根因 = 浅色 `--green:#0b7a55` + `--soft-green` 压在 `--panel2` 上合成出 `rgb(220,235,235)`。**更深的教训**：内置审计器 `auditContrast()` **只量「当前鼠标位置」下的状态** ⇒ 「鼠标移开就全过」把缺陷系统性掩盖了。修法：① 浅色 `--green` → `#0a6f4d`、`--soft-green` → `rgba(10,111,77,.10)`（hover 4.98:1 / 常态 5.36:1 / 对白 6.19:1）；② **审计器增加 hover 态复测**（给每个采样元素的祖言行强制加 `.waudit-hover`，底色与真实 `:hover` 一致）⇒ 采样量翻倍（123→238），hover 态缺陷从此进不了审计；③ **必须配阴性对照**（临时注入旧值 `#0b7a55`，验证审计器确实报出 3 处失败，再还原）⇒ 证明「全过」不是审计器坏了。**教训沉淀**：任何「这批数据已过时」的提示都要同时回答「它们还排在前面吗」—— 标注解决「看不出来」，排序解决「挡在前面」，**两者都要做**；总览卡与明细视图必须**共用同一个** `partitionDead()` 纯函数，否则同一个概念在两处给出两种答案。

- ~~**P3 · 最近动态含已删除文件 / 噪声条目**~~ —— **已于第二十三轮（v1.7.13）修复**：根因是「扫描快照 = 那一刻的真相」+ **打开前从不判存在性**。本轮用独立探针把两个后果分别量化：`shell.openPath(<缺失>)` → Promise **永不落地**（5/5 用例 25s 超时）+ **原生模态错误框**；`shell.showItemInFolder(<缺失>)` → **同步返回、什么都不做**（100% 静默失败）。修法：主进程打开前先判存在性（不存在直接返回错误串、**不调 shell**）+ `Promise.race` 15s 超时兜底；渲染层一次**批量** IPC 查存在性，失效行**置灰 + 划线 + 「已删除」角标**（角标占用「文件类型」那一格 ⇒ 零布局位移）。实测：缓存 60 条里 **36 条失效**（ps1×11 / png×23 / json×1 / log×1，全是上一轮 QA 临时文件），最近视图**恰好标出 36 条**、存活 24 条；点失效条目的「📂」与文件名都在 **1ms** 内弹出明确提示（修前：一个静默、一个永远挂起）。
- ~~**P3 · 扫描缓存里的"未来时间"**~~ —— **已证伪，不构成缺陷**：`main.log` 用 ISO **UTC** 时间戳（`06:48:11`）而系统本地时区是 +08:00（本地 `14:48`），二者差 8 小时是**正常表现**，不是 bug；缓存 `meta.scanTime=2026-11-16 13:47:54` 按本地时区解析的年龄 = **61 分钟**，与托盘菜单显示的「1 小时前（13:47）」**完全一致** ⇒ 「数据新鲜度」链路（标题栏 / 侧栏 / 托盘三处）当前是自洽的。**教训**：巡检里看起来像 bug 的现象必须先量化证伪，再决定要不要立项 —— 否则 BACKLOG 会攒满假线索、消耗下一轮的判断力。**本轮沿用这条教训**：接手线索 B 时同样先跑探针拿数据，结果**证伪了「主进程被挂起」这半句**（心跳证明主进程健康），从而把修法从「防主进程冻结」纠正为「**判存在性 + 不调 shell**」。
- **P3 · 「用 VS Code / 在终端打开」对失效路径无校验** —— **已于第二十四轮（v1.7.14）修复**：探针实测（修前）`openIn(<缺失>,'vscode')` → **照样 spawn** `cmd.exe /c code "<缺失>"` 且回报 `{ok:true}`；`openIn(<缺失>,'terminal')` → **照样 spawn** `wt.exe -d <缺失>` 且回报 `{ok:true}`；`openIn(<缺失>, default 兜底)` → **直调 `shell.openPath`** ⇒ 三条路都无保护 ⇒ 用户桌面上弹出 **VS Code / Windows Terminal 自己的报错窗**，而工作台**一句话都不说**（渲染层 `if (!r.ok) toast(...)` 永不触发）= **纯静默失败**。真实数据侧：缓存 59 个项目里 **2 个磁盘上已不存在**（`D:\wt-demo`、`D:\wt-prev`）。修法：`openIn` **入口统一判存在性**（缺失 → `{ok:false, msg:'路径已不存在（可能已被删除或移动）'}`、**不 spawn、不调 shell**），存在时行为完全不变，兜底分支加 `Promise.race` 15s 超时；渲染层仅补 `.catch()` 兜底 ⇒ **零新增 IPC、零契约变更**。实测：修后失效路径 `spawned = 0` / `openPathCalled = 0`、返回 `ok=false`；**跨进程 tasklist 监控（33 样本）delta = {Code:0, WT:0, cmd:0}**；真实鼠标点击 **658ms** 出错误 toast（dev 与打包版各一遍，断言 10/10 PASS）。
- **P3 · 项目雷达里的失效项目没有视觉标注**（第二十四轮自查发现）—— **已于第二十五轮（v1.7.15）修复**：v1.7.13 只给「最近动态」加了「已删除」角标，**项目视图没有** ⇒ 失效项目仍显示在雷达里，用户要点按钮才知道它没了。修法：复用 v1.7.13 已有的批量 `path:exists` 通道（**零新增 IPC**）给项目行也判存在性；失效行**置灰 + 名字划线 + 红色「已删除」角标（占用「类型徽标」那一格 ⇒ 零布局位移）** + 副标题改显「该路径已不存在（可能已被删除或移动）」+ 体量列改显「—/已失效」+ **去掉过期快照的「未提交 ●N」与琥珀条**；统计行追加「· 已删除 2」。实测 16/16 断言 PASS（dev + 打包版 v1.7.15 各一遍），点击失效项目**零外部进程被拉起**。
- **P2 · 项目行的操作按钮溢出栅格轨道、压住「体量」列文字**（第二十五轮 QA 目检 + 几何量测抓出，**既有缺陷**、非本轮引入）：`.prow` 的 `grid-template-columns` 声明了 **5 条轨道**，但 `.prow` 只有 **4 个子元素**（avatar / p-main / p-size / p-actions）⇒ `.p-actions` 被塞进 96px 的第 4 轨，而它要装 5 个按钮（≈189px）⇒ flex 溢出**向左**压到体量列（实测存活行重叠 **34~35px**、失效行 26px），同时末尾还留着一条**空轨道**在右侧空出 ≈186px 死区。 —— **已于第二十五轮（v1.7.15）修复**：改为 4 条轨道、末轨交给 `.p-actions` 自适应（`minmax(170px,auto)`）⇒ 实测**全表重叠 = 0px**（修前 34~35px）、右侧死区消失。**教训**：截图里看着「挤」的布局，**先量几何再下结论**（本轮靠 `Range.getBoundingClientRect()` 量出 34px 重叠才发现的真缺陷，纯目检只会觉得「有点挤」）。
